01 · EDITING PRIMITIVE92

jake-stewart/multicursor.nvim

补齐你当前配置里完全缺失的多光标能力，不替换 LSP、不碰文件树，也不侵入格式化链路。

  • 支持 normal / insert / replace / visual、undo / redo
  • 支持正则拆分光标、列对齐、每光标独立寄存器
  • 适合批量改结构相同但不值得写宏的代码
建议：直接试用 1,519 stars
02 · DAILY FRICTION88

gbprod/yanky.nvim

解决 Vim 最常见的真实摩擦：刚复制的内容被下一次删除覆盖。它把 yank / put 变成可回溯的数据结构，而不是一次性状态。

  • yank ring、历史选择器、粘贴后循环历史
  • 可直接用 shada 持久化，不必增加 sqlite 依赖
  • 映射会覆盖 y/p/P，必须检查现有键位
建议：直接试用 1,283 stars
03 · BACKEND WORKFLOW79

kndndrj/nvim-dbee

你有 SQL、Go、Proto、Docker 配置，但没有交互式数据库客户端。DBee 的 Go 后端正好补这个闭环。

  • 编辑器内连接、执行、浏览与导出查询结果
  • 无需依赖数据库 CLI；当前 Neovim 版本满足 ≥0.10
  • README 明示 Alpha，当前有 61 个 issue 与 16 个 PR；只按命令懒加载
建议：高频查库才装 1,311 stars

价值高，但现在装是错的

版本约束属于硬条件，不是“可能有点问题”。先升级并跑完现有配置回归，再引入这些插件。

kulala.nvim · 后端 API 工作流

HTTP、GraphQL、gRPC、WebSocket、OpenAPI、认证、断言和脚本都能留在 .http 文件里，长期价值比临时 curl 历史高。问题是最新版明确要求 Neovim 0.12+，你当前是 0.11.1。不要偷偷 pin 老版本制造维护债。

sidekick.nvim · AI CLI 工作流

它能把 Codex / Claude / Gemini CLI、上下文提示、diff 审阅和 tmux 会话放进 Neovim；你已有 snacks.nvim，接入条件不错。但最低要求是 Neovim 0.11.2，Copilot NES 还需要 Copilot LSP，而你的 copilot.lua 当前显式禁用。

两个看起来诱人、实际上只适合“替换”的项目

不要叠加 Oil 与 CodeDiff。 你的 Neo-tree 包含垃圾桶删除、按扩展名生成 Go/Proto/Rust 文件骨架；Diffview 则有自定义历史、merge-tool 和冲突选择键位。Oil / CodeDiff 只有在你愿意删掉原方案并重新验收工作流时才有价值。作为第二套入口共存，只会增加认知成本。
